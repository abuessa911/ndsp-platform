# NDSP — Final Frontend Governance Lock V1.0

**المنصة:** NDSP — Nawaf Decision Support Platform  
**الحالة:** Design & Implementation Governance Freeze  
**تاريخ الاعتماد:** 2026-07-24  
**النطاق:** بوابة المستخدم، الصفحات العامة داخل الحساب، تجربة الجوال والكمبيوتر، الترجمة، الباقات، الطبقات العامة، البيانات الحية، المحفظة، التنبيهات، الحساب والاشتراك، الاختبارات، والنشر.  
**القاعدة العليا:** لا يُنفذ أي تغيير يخالف هذا الملف إلا عبر إصدار حوكمة جديد موثق ومعتمد.

---

## 1. الهدف الملزم

هذا الملف يمنع:

- البناء العشوائي والتعديلات المتراكمة.
- إصلاح صفحة عبر كسر صفحة أخرى.
- حلول CSS المؤقتة التي تخفي السبب.
- تكرار القوائم أو السياق أو منطق الترجمة.
- عرض بيانات تجريبية بوصفها حية.
- كشف أسماء الطبقات الداخلية أو تفاصيل الحوكمة غير المصرح بها.
- النشر قبل اكتمال التصميم والوظائف والاختبارات والموافقة البصرية.
- العودة إلى الإنتاج عبر ترقيعات غير موثقة.

إصلاح الخطأ الحقيقي مسموح ومطلوب، بشرط معالجة السبب الجذري وإضافة اختبار يمنع تكراره.

---

## 2. قانون التغيير

كل تغيير يجب أن يصنف إلى أحد الأنواع التالية:

1. **Root Cause Bug Fix** — إصلاح سبب جذري مع اختبار ارتدادي.
2. **Approved Feature** — ميزة موجودة في هذا التجميد أو في إصدار حوكمة لاحق.
3. **Security Fix** — إصلاح أمني موثق مع تقييم أثر.
4. **Content/Translation Fix** — تعديل نص أو ترجمة دون كسر التخطيط.
5. **Release Engineering** — بناء، اختبار، نشر، تراجع، أو مراقبة.

ممنوع:

- Temporary Patch غير موثق.
- CSS Override خاص بصفحة واحدة لحل مشكلة مكون مشترك.
- نسخ منطق موجود بدل إصلاح المكون الأصلي.
- DOM translation patch.
- إخفاء عناصر حساسة بالـCSS مع استمرار إرسال بياناتها.
- نشر Hotfix دائم دون دمجه في المصدر وإضافة اختبار له.

## 3. بنية الإصدار والنشر

- الإصدار النهائي الجديد يبنى كنسخة مستقلة، وليس فوق `portal-v50`.
- مسار المعاينة المعتمد: `/portal-next/`.
- لا يتم تحويل الإنتاج إلا بعد موافقة بصرية صريحة.
- لا تعديل لـNginx أو إعادة تشغيل لخدمات الإنتاج دون:
  - Backup
  - Test Plan
  - Rollback
  - Verification
- أي فشل في بوابة إلزامية يمنع النشر.
- يجب تعطيل Source Maps في Build الإنتاج.
- لا تُرفع ملفات `.git` أو `.local` أو مخازن الحزم أو سجلات التطوير داخل حزمة النشر.

## 4. الهوية البصرية

- أسود/ذهبي ملكي بهوية NDSP.
- تباين واضح ومقروء، دون إفراط في التوهج أو الزخرفة.
- العربية RTL والإنجليزية LTR من المصدر نفسه.
- لا `letter-spacing` على النص العربي.
- لا نصوص إنجليزية غير مترجمة في الواجهة العربية.
- لا أحرف منفصلة أو رموز تجريبية أو أسماء متغيرات تظهر للمستخدم.
- لا تُستخدم الألوان وحدها لشرح الحالة؛ يجب وجود نص أو رمز واضح.

## 5. نظام المسافات والأحجام

### 5.1 مقياس المسافات

القيم المسموحة أساسًا:

- 4px: فصل دقيق.
- 8px: عناصر صغيرة.
- 12px: مجموعة داخلية.
- 16px: المسافة القياسية.
- 24px: حواف الكروت والأقسام.
- 32px: بين الأقسام الرئيسية.
- 48px: فصل الصفحات الكبيرة.

القيم العشوائية ممنوعة ما لم توثق كاستثناء تصميمي.

### 5.2 عرض المحتوى

- Desktop max width: 1440px.
- Desktop side padding: 24–32px.
- Tablet side padding: 20px.
- Mobile side padding: 14–16px.
- ممنوع التمرير الأفقي للصفحة.

### 5.3 النصوص

- عنوان الصفحة: 28–32px.
- عنوان القسم: 21–24px.
- عنوان الكرت: 16–18px.
- النص الأساسي: 15–16px.
- النص المساند: 13–14px.
- الأرقام الرئيسية: 28–38px.
- Inputs وButtons على الجوال: لا تقل عن 16px.
- العربية تستخدم line-height أوسع من الإنجليزية.

### 5.4 الكروت

- Desktop padding: 20–24px.
- Mobile padding: 16px.
- Border radius: 14–16px.
- Gap: 16–20px.
- الكروت النصية: `height:auto`.
- يمنع فرض ارتفاع ثابت على كرت نصي.
- تساوي الارتفاع مسموح فقط لبطاقات KPI والأسعار والطبقات والباقات المتشابهة.
- الكروت غير المتشابهة تستخدم `align-self:start`.
- الشبكات تستخدم `auto-fit/minmax` أو منطقًا مكافئًا.

قواعد إضافية:

- لا Entry/TP/Stop.

- يوضح الفرق بين قوة القراءة وجاهزية القرار.
- يوضح مسار الحالة: BLOCKED → ALLOWED → ARMED → EXECUTED عند الحاجة المهنية فقط.

## 13. التجربة والباقات

- مدة التجربة: 16 يومًا.
- أثناء التجربة: تظهر الطبقات العامة الخمس.
- بعد التجربة: الظهور حسب الباقة.
- المنع يجب أن يكون Server-side.
- CSS-only locking ممنوع.
- البطاقة المقفلة لا تعرض قيمًا أو نتائج مخفية.
- تظهر رسالة واضحة وزر ترقية.
- أسماء الباقات وأسعارها الدقيقة وإجمالي الحدود التجارية تحفظ كإعدادات قابلة للتكوين ولا تُدفن داخل مكونات العرض.

نموذج أولي للصلاحيات:

- Free: TDL.
- Basic: TDL + NMP.
- Professional: الطبقات العامة الخمس.
- Admin/Owner: الطبقات العامة الخمس مع أدوات الحوكمة المصرح بها.

هذا التوزيع قابل للتعديل بقرار تجاري موثق دون تغيير بنية التطبيق.
