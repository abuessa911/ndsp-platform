# NDSP — الحوكمة القانونية الموحّدة

**المعرّف:** `NDSP-CANONICAL-GOVERNANCE-001`
**الإصدار:** `1.0.0`
**تاريخ السريان:** `2026-07-30`
**الأولوية:** أعلى مرجع حوكمة للمشروع بعد تثبيته.

## 1. قاعدة الأولوية

عند التعارض، الترتيب هو:

1. هذا المرجع.
2. العقود والـregistries الموجودة داخل `governance/canonical-v1/`.
3. قرارات إصدار أحدث معتمدة صراحة من المالك.
4. وثائق Superseded لأغراض التاريخ فقط.
5. الكود القديم لا يتغلب على الحوكمة الجديدة، لكنه لا يُعدل دون source lock واختبارات وrollback.

## 2. قواعد ثابتة

- NDSP منصة دعم قرار تفسيرية، لا تصدر أوامر تداول.
- لا Entry/TP/Stop في العقد العام.
- Source-first only.
- لا تعديل للحزم المصغرة أو DOM runtime patches.
- لا نشر دون Backup + Test Plan + Rollback + Verification.
- لا قيمة مختلقة في Live Mode.
- لا حذف خدمة أو عقد قبل consumer evidence.
- لا حذف نهائي للحوكمة السابقة قبل نجاح أرشفة ورجوع.
- الـ16 طبقة هي قلب القرار؛ ليست 16 microservices إلزامية.
- الأخبار لا تغيّر TDL مباشرة.
- ترتيب المخاطر: USD/Macro → Risk → Devil’s Advocate.
- Beginner وProfessional يعرضان نفس الحقيقة بمستويين مختلفين.

## 3. النطاق الحاكم الحالي

- التقرير الرئيسي للنواقص.
- سجل P0/P1/P2.
- قفل source ومسار runtime.
- عقود dual scenario وdata quality.
- الواجهة النهائية.
- الباقات والـentitlements.
- النسخ والاستعادة.
- الاختبارات والإطلاق.

## 4. سياسة Superseded

أي وثيقة سابقة يتم أرشفتها تحت:

```text
governance/archive/superseded/<timestamp>/
```

وتحصل على manifest يحفظ:

- المسار الأصلي.
- SHA-256.
- تاريخ الأرشفة.
- سبب الاستبدال.
- المرجع الجديد.

## 5. التغيير

أي تغيير جديد يجب أن يحدد:

- النوع.
- السبب.
- الملفات.
- الاختبارات.
- المخاطر.
- الرجوع.
- الإصدار.
- موافقة المالك عند الحاجة.
