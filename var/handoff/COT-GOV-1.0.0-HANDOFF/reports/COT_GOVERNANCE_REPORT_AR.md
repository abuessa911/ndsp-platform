## 3. المصطلحات الرسمية

### 3.1 دلتا الغلبة

دلتا الغلبة هي الفارق العددي بين قيمة عقود الشراء وقيمة عقود البيع داخل السطر أو المجموعة نفسها:

`Dominance Delta = Long − Short`

هذه الدلتا ليست فارقاً زمنياً بين تقريرين.

قرار الاتجاه يعتمد على المقارنة المباشرة:

- Long > Short: صاعد.
- Short > Long: هابط.
- Long = Short: محايد.

فارق عقد واحد يكفي لتحديد الاتجاه.

### 3.2 الاتجاه والصراحة والأفق

النتائج الرسمية:

- صاعد صريح — ذو أفق ممتد.
- هابط صريح — ذو أفق ممتد.
- صاعد غير صريح — ذو أفق ضيق.
- هابط غير صريح — ذو أفق ضيق.
- محايد عند التساوي التام.

التصنيف:

- إذا كان أحد الجانبين موجباً والآخر سالباً:
  صريح — ذو أفق ممتد.
- إذا كان الجانبان من العلامة نفسها:
  غير صريح — ذو أفق ضيق.
- إذا تساوى الجانبان تماماً:
  محايد.

الحالة الحدية التي يكون فيها أحد الطرفين صفراً والآخر غير صفر تصنف مبدئياً ضمن غير الصريح والأفق الضيق، ما لم يصدر قرار حوكمة لاحق يغير ذلك.

## 4. النمط الاستثماري

### 4.1 المصدر الرسمي للاتجاه الكلي

يستخدم النمط الاستثماري:

`Asset Manager Positions Long`
مقابل:
`Asset Manager Positions Short`

فقط.

لا تدخل فئة الآخرين في مخرج CORE الاستثماري الرسمي.

### 4.2 العناصر المعطلة

في النمط الاستثماري تكون العناصر التالية معطلة:

- Day Control.
- Daily Controller.
- TDL-M&L.
- TDL-S.
- Speculation Timing.
- أي منطق يختار فئة مسيطرة حسب اليوم.

لا يجوز استدعاؤها حتى كتأكيد ثانوي.

### 4.3 الدعم الأسبوعي

تستخدم بيانات:

`Asset Manager Changes Long`
مقابل:
`Asset Manager Changes Short`

لغرض واحد فقط:

تحديد ما إذا كان الاتجاه الأسبوعي يدعم الاتجاه الكلي.

إذا اتفق اتجاه Changes مع اتجاه Positions:

`weeklySupport = CONFIRMED`

إذا اختلف:

`weeklySupport = NOT_CONFIRMED`

وفي حالة الاختلاف:

- لا يتغير الاتجاه الكلي.
- لا يخفى الاتجاه الكلي.
- لا يعكس الاتجاه.
- لا يخفض أو يرفع تصنيفه.
- تظهر للمستخدم العبارة:
  **الدعم الأسبوعي غير متحقق**

### 4.4 مثال تقرير 21 يوليو

Positions لمدراء الأصول:

- Long: 4,684
- Short: 1,957
- دلتا الغلبة: +2,727
- النتيجة:
  **صاعد غير صريح — ذو أفق ضيق**

Changes لمدراء الأصول:

- Long: -95
- Short: -7
- دلتا الغلبة: -88
- النتيجة:
  **هابط غير صريح — ذو أفق ضيق**

النتيجة الاستثمارية الرسمية:

- الاتجاه الكلي:
  **صاعد غير صريح — ذو أفق ضيق**
- الدعم الأسبوعي:
  **الدعم الأسبوعي غير متحقق**

## 5. النمط المضاربي

### 5.1 مصدر البيانات

النمط المضاربي يستخدم Changes فقط.

لا يستخدم Positions لتحديد الاتجاه المضاربي.

### 5.2 منطق الفئة المسيطرة

يتم أولاً تحديد الفئة المسيطرة وفق منظور أيام السيطرة المختار، ثم تستخدم Changes الخاصة بالفئة المسيطرة فقط.

### 5.3 CORE

عندما تكون السيطرة لطويلي الأمد:

- مدراء الأصول فقط.

عندما تكون السيطرة لقصيري الأمد:

- الرافعات المالية فقط.

### 5.4 EXPANDED

عندما تكون السيطرة لطويلي الأمد:

- مدراء الأصول + الآخرون.

عندما تكون السيطرة لقصيري الأمد:

- الرافعات المالية + المتاجرين.

يتم جمع Long مع Long، وShort مع Short، ثم المقارنة.

### 5.5 TDL-M&L وTDL-S

يسمح بتشغيلهما داخل النمط المضاربي فقط.

يحظر تشغيلهما داخل النمط الاستثماري.

يجب أن تكون قواعدهما قابلة للتعديل من ملفات إعداد وعقود واضحة، لا مدفونة داخل منطق المحرك.

لم يتم حتى الآن تزويد الحزمة بالتعريف التفصيلي لمنطق TDL-M&L أو TDL-S القديم، لذلك تتعامل النسخة المرجعية معهما بوصفهما محولين قابلين للحقن، ولا تخترع سلوكاً جديداً.

## 7. التوقيت الرسمي

### 7.1 UTC

UTC هو المرجع الوحيد لـ:

- بداية ونهاية اليوم.
- بداية ونهاية الأسبوع.
- أيام السيطرة.
- تاريخ تفعيل التقرير.
- قياس حركة السعر.
- التخزين.
- العقود.
- السجلات.
- الاختبارات.
- سجل التدقيق.

التوقيت المحلي يستخدم للعرض فقط.

### 7.2 بداية الأسبوع

- بداية الأسبوع: الاثنين 00:00:00Z.
- نهاية الأسبوع: بداية الاثنين التالي.
- يستخدم نطاق نصف مفتوح:
  `effectiveFrom <= timestamp < effectiveUntil`

### 7.3 تفعيل تقرير COT

تقرير الثلاثاء لا يستخدم مباشرة في الأيام التالية.

يبدأ تطبيقه من الاثنين التالي الساعة 00:00 UTC.

مثال:

- تاريخ التقرير: 2026-07-21.
- بداية التطبيق: 2026-07-27T00:00:00Z.
- نهاية التطبيق: 2026-08-03T00:00:00Z.

## 8. CORE وEXPANDED

### 8.1 CORE

هو النموذج الرسمي المؤقت.

الاستثمار:

- Asset Manager Positions فقط.
- Asset Manager Changes للدعم الأسبوعي فقط.

المضاربة:

- Asset Manager Changes عند سيطرة طويلي الأمد.
- Leveraged Funds Changes عند سيطرة قصيري الأمد.

CORE هو الوحيد الذي:

- ينتج النتيجة الرسمية.
- يكتب في مخزن النتائج الرسمية.
- يظهر للمستخدم.
- يصل إلى Public API.

### 8.2 EXPANDED

هو نموذج اختبار موازي.

الاستثمار التجريبي:

- Asset Manager + Other Reportables.

المضاربة التجريبية:

- Asset Manager + Other Reportables.
- Leveraged Funds + Dealer/Intermediary.

حالة التشغيل:

`SHADOW_MODE`

القيود:

- لا يغير CORE.
- لا يكتب في النتائج الرسمية.
- لا يظهر للمستخدم.
- لا يرسل تنبيهات عامة.
- لا ينفذ قرارات.
- لا يترقى تلقائياً.

### 8.3 الوصول

المستخدم النهائي:

- يرى CORE فقط.

المشرف والمطور:

- يرى CORE.
- يرى EXPANDED.
- يرى حالة الاختبار.
- يرى الاتفاق والاختلاف.
- يرى الإصدارات والسجلات.
