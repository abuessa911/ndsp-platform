## 3. المصطلحات الرسمية

### 3.1 دلتا الغلبة

دلتا الغلبة هي الفارق العددي بين قيمة عقود الشراء وقيمة عقود البيع داخل السطر أو المجموعة نفسها:

`Dominance Delta = Long − Short`

هذه الدلتا ليست فارقاً زمنياً بين تقريرين.

قرار الاتجاه يعتمد على المقارنة المباشرة:

- Long > Short: صاعد.
- Short > Long: هابط.
- Long = Short: محايد.

فارق عقد واحد يكفي لتحديد الاتجاه.

### 3.2 الاتجاه والصراحة والأفق

النتائج الرسمية:

- صاعد صريح — ذو أفق ممتد.
- هابط صريح — ذو أفق ممتد.
- صاعد غير صريح — ذو أفق ضيق.
- هابط غير صريح — ذو أفق ضيق.
- محايد عند التساوي التام.

التصنيف:

- إذا كان أحد الجانبين موجباً والآخر سالباً:
  صريح — ذو أفق ممتد.
- إذا كان الجانبان من العلامة نفسها:
  غير صريح — ذو أفق ضيق.
- إذا تساوى الجانبان تماماً:
  محايد.

الحالة الحدية التي يكون فيها أحد الطرفين صفراً والآخر غير صفر تصنف مبدئياً ضمن غير الصريح والأفق الضيق، ما لم يصدر قرار حوكمة لاحق يغير ذلك.

## 4. النمط الاستثماري

### 4.1 المصدر الرسمي للاتجاه الكلي

يستخدم النمط الاستثماري:

`Asset Manager Positions Long`
مقابل:
`Asset Manager Positions Short`

فقط.

لا تدخل فئة الآخرين في مخرج CORE الاستثماري الرسمي.

### 4.2 العناصر المعطلة

في النمط الاستثماري تكون العناصر التالية معطلة:

- Day Control.
- Daily Controller.
- TDL-M&L.
- TDL-S.
- Speculation Timing.
- أي منطق يختار فئة مسيطرة حسب اليوم.

لا يجوز استدعاؤها حتى كتأكيد ثانوي.

### 4.3 الدعم الأسبوعي

تستخدم بيانات:

`Asset Manager Changes Long`
مقابل:
`Asset Manager Changes Short`

لغرض واحد فقط:

تحديد ما إذا كان الاتجاه الأسبوعي يدعم الاتجاه الكلي.

إذا اتفق اتجاه Changes مع اتجاه Positions:

`weeklySupport = CONFIRMED`

إذا اختلف:

`weeklySupport = NOT_CONFIRMED`

وفي حالة الاختلاف:

- لا يتغير الاتجاه الكلي.
- لا يخفى الاتجاه الكلي.
- لا يعكس الاتجاه.
- لا يخفض أو يرفع تصنيفه.
- تظهر للمستخدم العبارة:
  **الدعم الأسبوعي غير متحقق**

### 4.4 مثال تقرير 21 يوليو

Positions لمدراء الأصول:

- Long: 4,684
- Short: 1,957
- دلتا الغلبة: +2,727
- النتيجة:
  **صاعد غير صريح — ذو أفق ضيق**

Changes لمدراء الأصول:

- Long: -95
- Short: -7
- دلتا الغلبة: -88
- النتيجة:
  **هابط غير صريح — ذو أفق ضيق**

النتيجة الاستثمارية الرسمية:

- الاتجاه الكلي:
  **صاعد غير صريح — ذو أفق ضيق**
- الدعم الأسبوعي:
  **الدعم الأسبوعي غير متحقق**

## 5. النمط المضاربي

### 5.1 مصدر البيانات

النمط المضاربي يستخدم Changes فقط.

لا يستخدم Positions لتحديد الاتجاه المضاربي.

### 5.2 منطق الفئة المسيطرة

يتم أولاً تحديد الفئة المسيطرة وفق منظور أيام السيطرة المختار، ثم تستخدم Changes الخاصة بالفئة المسيطرة فقط.

### 5.3 CORE

عندما تكون السيطرة لطويلي الأمد:

- مدراء الأصول فقط.

عندما تكون السيطرة لقصيري الأمد:

- الرافعات المالية فقط.

### 5.4 EXPANDED

عندما تكون السيطرة لطويلي الأمد:

- مدراء الأصول + الآخرون.

عندما تكون السيطرة لقصيري الأمد:

- الرافعات المالية + المتاجرين.

يتم جمع Long مع Long، وShort مع Short، ثم المقارنة.

### 5.5 TDL-M&L وTDL-S

يسمح بتشغيلهما داخل النمط المضاربي فقط.

يحظر تشغيلهما داخل النمط الاستثماري.

يجب أن تكون قواعدهما قابلة للتعديل من ملفات إعداد وعقود واضحة، لا مدفونة داخل منطق المحرك.

لم يتم حتى الآن تزويد الحزمة بالتعريف التفصيلي لمنطق TDL-M&L أو TDL-S القديم، لذلك تتعامل النسخة المرجعية معهما بوصفهما محولين قابلين للحقن، ولا تخترع سلوكاً جديداً.

## 7. التوقيت الرسمي

### 7.1 UTC

UTC هو المرجع الوحيد لـ:

- بداية ونهاية اليوم.
- بداية ونهاية الأسبوع.
- أيام السيطرة.
- تاريخ تفعيل التقرير.
- قياس حركة السعر.
- التخزين.
- العقود.
- السجلات.
- الاختبارات.
- سجل التدقيق.

التوقيت المحلي يستخدم للعرض فقط.

### 7.2 بداية الأسبوع

- بداية الأسبوع: الاثنين 00:00:00Z.
- نهاية الأسبوع: بداية الاثنين التالي.
- يستخدم نطاق نصف مفتوح:
  `effectiveFrom <= timestamp < effectiveUntil`

### 7.3 تفعيل تقرير COT

تقرير الثلاثاء لا يستخدم مباشرة في الأيام التالية.

يبدأ تطبيقه من الاثنين التالي الساعة 00:00 UTC.

مثال:

- تاريخ التقرير: 2026-07-21.
- بداية التطبيق: 2026-07-27T00:00:00Z.
- نهاية التطبيق: 2026-08-03T00:00:00Z.

## 8. CORE وEXPANDED

### 8.1 CORE

هو النموذج الرسمي المؤقت.

الاستثمار:

- Asset Manager Positions فقط.
- Asset Manager Changes للدعم الأسبوعي فقط.

المضاربة:

- Asset Manager Changes عند سيطرة طويلي الأمد.
- Leveraged Funds Changes عند سيطرة قصيري الأمد.

CORE هو الوحيد الذي:

- ينتج النتيجة الرسمية.
- يكتب في مخزن النتائج الرسمية.
- يظهر للمستخدم.
- يصل إلى Public API.

### 8.2 EXPANDED

هو نموذج اختبار موازي.

الاستثمار التجريبي:

- Asset Manager + Other Reportables.

المضاربة التجريبية:

- Asset Manager + Other Reportables.
- Leveraged Funds + Dealer/Intermediary.

حالة التشغيل:

`SHADOW_MODE`

القيود:

- لا يغير CORE.
- لا يكتب في النتائج الرسمية.
- لا يظهر للمستخدم.
- لا يرسل تنبيهات عامة.
- لا ينفذ قرارات.
- لا يترقى تلقائياً.

### 8.3 الوصول

المستخدم النهائي:

- يرى CORE فقط.

المشرف والمطور:

- يرى CORE.
- يرى EXPANDED.
- يرى حالة الاختبار.
- يرى الاتفاق والاختلاف.
- يرى الإصدارات والسجلات.

## 3. Official terminology

### 3.1 Dominance delta

Dominance delta is the numerical difference between Long and Short values inside the same row or aggregated group:

`Dominance Delta = Long − Short`

It is not a time-series difference between reports.

Direction is determined by direct comparison:

- Long > Short: Bullish.
- Short > Long: Bearish.
- Long = Short: Neutral.

A difference of one contract is sufficient.

### 3.2 Direction, explicitness, and horizon

Official labels:

- Bullish explicit — extended horizon.
- Bearish explicit — extended horizon.
- Bullish non-explicit — narrow horizon.
- Bearish non-explicit — narrow horizon.
- Neutral only on exact equality.

Classification:

- Opposite signs:
  explicit — extended horizon.
- Same sign:
  non-explicit — narrow horizon.
- Exact equality:
  neutral.

The initial implementation classifies a zero/non-zero pair as non-explicit and narrow unless a later governance decision changes that boundary rule.

---

## 4. Investment mode

### 4.1 Official total direction

Investment mode compares:

`Asset Manager Positions Long`

against:

`Asset Manager Positions Short`

only.

Other Reportables do not participate in official investment CORE output.

### 4.2 Disabled components

The following are disabled in investment mode:

- Day Control.
- Daily Controller.
- TDL-M&L.
- TDL-S.
- Speculation Timing.
- Any controller selection based on weekday.

They must not be invoked even as secondary confirmation.

### 4.3 Weekly support

Investment mode compares:

`Asset Manager Changes Long`

against:

`Asset Manager Changes Short`

only to determine whether the weekly direction supports the total direction.

On agreement:

`weeklySupport = CONFIRMED`

On disagreement:

`weeklySupport = NOT_CONFIRMED`

Disagreement:

- Does not change total direction.
- Does not hide total direction.
- Does not reverse total direction.
- Does not upgrade or downgrade it.
- Displays:
  **Weekly support is not confirmed.**

### 4.4 July 21 example

Asset Manager Positions:

- Long: 4,684
- Short: 1,957
- Dominance delta: +2,727
- Result:
  **Bullish non-explicit — narrow horizon**

Asset Manager Changes:

- Long: -95
- Short: -7
- Dominance delta: -88
- Result:
  **Bearish non-explicit — narrow horizon**

Official investment output:

- Total direction:
  **Bullish non-explicit — narrow horizon**
- Weekly support:
  **Weekly support is not confirmed**

## 5. Speculation mode

### 5.1 Dataset

Speculation mode uses Changes only.

Positions must not determine speculation direction.

### 5.2 Controlling category

The engine identifies the controlling side according to the selected day-control perspective and then uses only the controlling category’s Changes.

### 5.3 CORE

Long-term controller:

- Asset Managers only.

Short-term controller:

- Leveraged Funds only.

### 5.4 EXPANDED

Long-term controller:

- Asset Managers + Other Reportables.

Short-term controller:

- Leveraged Funds + Dealer/Intermediary.

Long values are added to Long values, and Short values to Short values before comparison.

### 5.5 TDL-M&L and TDL-S

They are allowed only in speculation mode.

They are forbidden in investment mode.

Their rules must be configurable through explicit files and contracts rather than hidden inside engine code.

The existing detailed semantics have not yet been supplied. The reference implementation therefore exposes injectable timing adapters and does not invent undocumented TDL behavior.

## 7. Canonical timing

### 7.1 UTC

UTC is the sole reference for:

- Day boundaries.
- Week boundaries.
- Day control.
- Report activation.
- Price measurement.
- Storage.
- Contracts.
- Logs.
- Tests.
- Audit records.

Local time is display-only.

### 7.2 Week boundary

- Week begins Monday at 00:00:00Z.
- Week ends at the next Monday boundary.
- Half-open interval:
  `effectiveFrom <= timestamp < effectiveUntil`

### 7.3 Report activation

A Tuesday COT report becomes effective on the following Monday at 00:00 UTC.

Example:

- Report date: 2026-07-21.
- Effective from: 2026-07-27T00:00:00Z.
- Effective until: 2026-08-03T00:00:00Z.
